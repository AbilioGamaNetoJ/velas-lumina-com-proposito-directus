## How to Use This File

This file is the **entry point** for AI tools interacting with the project. As of 2026-07-06 this project runs two complementary systems:

1. **dotcontext** (`.context/`) — the project's context/harness layer: durable docs, agent playbooks, on-demand skills (including the PREVC workflow), plans, and runtime state. Consumed via the `dotcontext` MCP server if configured on your machine (`context`, `plan`, `workflow-*`, `agent`, `skill`, `harness`, `sync` tools), or just by reading the markdown directly.
2. **Claude Code skills** (`.claude/skills/`) — 14 skills installed from the `@tech-leads-club/agent-skills` registry, native Claude Code skills invoked automatically when their trigger matches.

> **Legacy:** `.agents/` (custom-built AG Kit — 20 agents, 45 skills, 13 workflow files) predates this setup and is kept only for historical reference. Do not add to it; new agents/skills/docs go in `.context/` or `.claude/skills/`.

### Which Tool Reads What

| Tool | Reads |
|---|---|
| **Claude Code** | `CLAUDE.md` -> this file; skills in `.claude/skills/`; optionally the `dotcontext` MCP server |
| **Gemini CLI / Antigravity** | `GEMINI.md` -> this file |
| **OpenCode** | Via `@AGENTS.md` mention |
| **Any dotcontext-integrated tool** | `.context/` directly, or the `dotcontext` MCP server |

## Design Context

Frontend/UI work is governed by two files at the project root, generated by the `impeccable` Claude Code skill:

- **[PRODUCT.md](./PRODUCT.md)** — register (`brand`), users, brand personality, anti-references, strategic design principles.
- **[DESIGN.md](./DESIGN.md)** — visual system: colors (Terracota Queimada + Ivory Quente + Mel Dourado), typography (Playfair Display + DM Sans), components, Do's/Don'ts (includes real doc/code drift found on generation: 3 different WhatsApp CTA styles, aroma tags styled two different ways, 3 ad-hoc shadow values instead of the `.shadow-ambient` token, and a repeating uppercase-eyebrow badge above nearly every section).

Read both before any UI/visual change. Structured design commands (`critique`, `audit`, `polish`, `document`, etc.) are documented in `.claude/skills/impeccable/SKILL.md`.

## Project Documentation (`.context/docs/`)

> **`.context/docs/` is the canonical source of truth for AI agents.**
> `README.md` is the entry point for human developers.

| Doc | Covers |
|---|---|
| `project-overview.md` | Vision, quick facts, entry points, getting-started checklist |
| `architecture.md` | Layers, ADR history, design patterns, external dependencies, risks |
| `development-workflow.md` | Branching, local dev commands, review expectations |
| `testing-strategy.md` | Current 0% coverage, planned Vitest/Playwright setup, priority order |
| `security.md` | Auth model (none), secret scoping, known open items |
| `glossary.md` | Domain types, Directus schema, business rules |
| `tooling.md` | Scripts, AI agent tooling, IDE setup |

### Reading Protocol (for AI)

Before any task: read `project-overview.md`, then `architecture.md`, then whichever doc matches the task area (`testing-strategy.md` for tests, `security.md` for anything touching secrets/tokens, etc.).

After a significant task: update the relevant `.context/docs/*.md` file if something changed, and **antes de commitar**, preencha a seção `[Não lançado]` do `CHANGELOG.md` se a mudança for importante (visual, arquitetural, nova feature, performance, SEO). Se a mudança não for importante (ex.: ajuste de comentário, refactor sem efeito visível), não é necessário alterar o changelog. Se um workflow PREVC estiver ativo (`workflow-init` foi chamado), o harness rastreia o progresso em `.context/runtime/workflows/` em vez de um arquivo de estado editado manualmente.
