### Adicionado (SEO + GEO)

- **Sitemap dinâmico via ISR** (`app/sitemap.ts`): substitui por completo o `next-sitemap` (pacote removido de `package.json`/`package-lock.json`, `postbuild` removido, `next-sitemap.config.cjs` deletado). Antes, os três arquivos gerados (`public/sitemap.xml`, `public/sitemap-0.xml`, `public/robots.txt`) ficavam commitados no git com o domínio do build local (`http://localhost:3001`) — confirmado servindo isso **em produção** (`https://velasartesanais.luminacomproposito.com.br/sitemap.xml` retornava `localhost`), impedindo o Google Search Console de descobrir qualquer URL do site. Agora o sitemap é gerado pelo App Router nativo do Next.js com `revalidate = 3600` — novos produtos cadastrados no Directus são incluídos automaticamente em até 1 hora, sem build/redeploy, e o domínio vem sempre de `SITE_URL` em tempo de request (sem risco de artefato estático desatualizado ir parar no git de novo). **Pendente:** confirmar a env var `SITE_URL=https://velasartesanais.luminacomproposito.com.br` no ambiente de Production da Vercel.
- **`robots.ts` dinâmico** (`app/robots.ts`): substitui o `public/robots.txt` estático que apontava para `localhost` em produção. Agora usa `SITE_URL` corretamente. Inclui permissão explícita para crawlers de IA (`GPTBot`, `Claude-Web`, `PerplexityBot`) para favorecer citações em ferramentas de GEO (Perplexity, ChatGPT, Claude, Gemini).
- **Schema `Organization`** no layout raiz: informa ao Google nome da marca, URL, logo e Instagram — essencial para o Knowledge Panel.
- **Schema `WebSite`** no layout raiz: identifica a marca como entidade (nome, URL, descrição, idioma) para o Google.
- **Schema `FAQPage`** na home (`app/page.tsx`): indexa as perguntas frequentes como rich results no Google e aumenta taxa de citação em IAs como Perplexity e ChatGPT.
- **Schema `LocalBusiness`** na home: endereço (Florianópolis/SC), telefone (WhatsApp), horário de funcionamento e links sociais — fundamental para aparecer no Google Maps e buscas com intenção local ("velas artesanais Florianópolis").
- **Schema `BreadcrumbList`** na página de produto: melhora a navegação nos rich results do Google.
- **Schema `Product` enriquecido**: adicionados `brand` e `seller` ao schema existente — aumenta confiança e elegibilidade para rich results de produto.
- **OG image com URL absoluta garantida**: tanto no layout raiz quanto na página de produto, a OG image agora sempre tem URL absoluta (Directus ou fallback `SITE_URL/images/lumina-velas.jpeg`), corrigindo pré-visualizações quebradas no WhatsApp e redes sociais.
- **Keywords e `authors`** no metadata do layout raiz.
- **`alternates.canonical`** em cada página de produto, evitando conteúdo duplicado percebido pelo Google.

### Corrigido

- **Carrossel "Nossas Essências Autorais" (`components/ProductCarousel.tsx`) — dois bugs.** (1) Produtos apareciam duplicados quando a lista filtrada/pesquisada tinha menos de 6 itens: o carrossel triplicava os slides para "encher" o loop infinito (`[...arr, ...arr, ...arr].slice(0, Math.max(6, count * 2))`), então buscar "cruz" (1 resultado) mostrava o mesmo produto 3 vezes, e o filtro "Arranjos" (3 produtos) mostrava 6 (pares repetidos). Removida a duplicação — os slides renderizados agora são sempre exatamente a lista real, sem preenchimento artificial. (2) Clicar nas setas ou pontinhos de navegação podia pular índices e resetar antes de chegar no último ponto: o plugin de autoplay (`embla-carousel-autoplay`) continuava avançando sozinho em segundo plano, correndo em paralelo com o clique manual, porque `stopOnInteraction` só reage a arrastar (drag) — clique em botão externo chama a API do Embla diretamente e nunca disparava esse listener. Corrigido parando o autoplay explicitamente (`autoplay.stop()`) em toda navegação manual (seta ou ponto). De brinde, os pontinhos (`scrollSnaps`) só eram recalculados na montagem do componente e ficavam desatualizados quando a quantidade de slides mudava (filtro/busca); agora são recalculados a cada `reInit` do Embla.
- **Campo "Galeria de Imagens" (`produtos.imagens`) quebrado no painel do Directus desde a migração original.** Criado com `interface: 'file'` (widget de arquivo único, para relações M2O) em vez de `interface: 'files'` (widget de galeria, para a relação M2M via `produtos_imagens`) — o painel tentava renderizar uma lista de arquivos com um componente feito para um único arquivo. A leitura de dados pelo frontend nunca foi afetada (não depende de `interface`, só de `special`/`relations`); o problema era só na edição pelo painel. Corrigido ao vivo e em `scripts/directus-migrate-pt-br.mjs`.
- **Pré-visualização de `produtos` e `categorias` no painel do Directus (listagem antes de abrir o item).** `produtos` mostrava só o nome (`display_template: '{{nome}}'`); passou a mostrar nome, foto de capa e nome da categoria, nesta ordem (`'{{nome}} {{imagem}} {{categoria.nome}}'`). O campo `categoria` (relação m2o) não tinha `display` configurado, então em qualquer lugar do painel onde esse relacionamento aparecia como preview/coluna ele caía no valor cru (o ID numérico da categoria) em vez do nome — corrigido com `display: 'related-values'` + `display_options.template: '{{nome}}'`. `categorias` passou de só nome para nome + identificador (slug): `'{{nome}} {{slug}}'`. Mudança só na pré-visualização/seleção do painel administrativo — não afeta o que é exibido no site. Corrigido ao vivo e em `scripts/directus-migrate-pt-br.mjs`.

- **Flow de auto-geração de slug (`produtos`/`categorias`), finalmente ativo em produção.** A causa raiz documentada anteriormente ("a mutação do payload pela operação `exec` não estava sendo aplicada", entrada de 2026-07-08 abaixo) estava incompleta: o problema real é que `trigger: "hook"` é um valor que a API aceita sem erro de validação mas que o registrador de eventos do Directus 11 ignora silenciosamente — o valor correto é `trigger: "event"`. Além disso, para o tipo `action` (non-blocking), o payload do item disparador chega em `data.$trigger.payload` dentro da operação `exec`, não em `data.payload` (isso só vale para o tipo `filter`/blocking). Com essas duas correções e um segundo operation (`item-update`, gravando via `{{$trigger.collection}}`/`{{$trigger.key}}`/`{{gerar_slug.slug}}`, `emitEvents: false`), o flow foi testado e confirmado funcionando em `produtos` e `categorias`.

### Adicionado

- **Opções de quantidade por produto, com preço próprio.** Dois campos novos em `produtos` no Directus: `produto_unitario` (checkbox — quando marcado, o produto é vendido como peça única e nenhum seletor aparece na página) e `quantidades` (repeater — uma linha por quantidade oferecida, cada uma com seu próprio preço; as opções disponíveis hoje são 20, 50 e 100 unidades, mas o cliente pode adicionar quantas linhas quiser no admin do Directus). Se o preço de uma linha for deixado em branco, `lib/directus/get-products.ts` calcula automaticamente `quantidade × preço padrão do produto` — a cliente só precisa preencher o preço quando quiser um valor diferente desse cálculo (ex.: desconto por volume). Na página do produto, quando há quantidades cadastradas e o produto não é unitário, um seletor ("Quantidade") aparece entre a descrição e os botões de ação, atualizando o preço exibido, o item adicionado à cesta (`lib/use-cart.ts` — carrinho agora trata cada combinação produto+quantidade como uma linha própria) e a mensagem pré-preenchida do botão "Orçar no WhatsApp". A quantidade escolhida também aparece no item do carrinho (`components/CartDrawer.tsx`) e na mensagem final de pedido (`lib/whatsapp.ts`). **Nota técnica:** os dois campos originalmente ficavam dentro de um grupo visual (`opcoes_venda`), mas um bug identificado nesta instância do Directus 11.17.4 faz qualquer campo do tipo grupo (`special:['group']`) sumir da listagem que o painel usa para montar o formulário. ### Segurança

- Identificado (não corrigido neste commit) vazamento de um access token do Directus MCP em texto puro no histórico do git, commit `e5aeb54` (`.agents/mcp_config.json`). Decisão: rotacionar o token no painel do Directus, sem reescrever o histórico do git (repo privado). O token vazado também está hoje em `~/.claude.json` (config local do usuário, não versionada) — atualizar lá após a rotação.
- `.gitignore` atualizado para bloquear `.mcp.json` e qualquer `**/mcp_config.json`/`**/mcp-config.json`, evitando repetição do vazamento acima. **Atenção:** `.agents/mcp_config.json` já está rastreado pelo git desde antes dessa regra — o `.gitignore` sozinho não impede que ele continue sendo versionado; para isso é preciso `git rm --cached .agents/mcp_config.json` também.
- `lib/directus.ts`: `staticToken()` agora só é anexado ao cliente Directus quando `DIRECTUS_TOKEN` está definido — antes, o token (inclusive um token admin em ambiente de produção) era sempre enviado, mesmo para as leituras públicas do site, ampliando desnecessariamente o dano de um eventual vazamento. Testado sem token: as 5 collections/singletons (`products`, `categories`, `site_settings`, `faqs`, `privacy_policy`) respondem `200` via a role `Public` do Directus, tanto localmente (`npm run dev`) quanto por `curl` direto na API. Recomendação: **não configurar `DIRECTUS_TOKEN` na Vercel** — deixar as leituras de produção dependerem só da role `Public`; usar um token admin apenas localmente, para rodar `scripts/setup-directus-content.mjs`.
