## [Não lançado]

### Corrigido

- Documentação para IA (`.context/docs/*.md`, `.context/agents/*.md`, `.context/skills/*/SKILL.md`, `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`) atualizada para refletir a migração do CMS de Sanity para Directus v11, concluída em 2026-06-27/28 mas nunca reconciliada nesses arquivos (alguns chegavam a afirmar o oposto da realidade). Detalhes: env vars (`NEXT_PUBLIC_DIRECTUS_URL`/`DIRECTUS_TOKEN` em vez de `SANITY_*`), camada de dados (`lib/directus/get-*.ts`), schema (collections/singletons Directus em vez de `sanity/schemaTypes/`), remoção de referências à rota `/studio` (não existe mais), e correção do risco #1 do `architecture.md` (produto detail já lê do CMS via `getProductBySlug()`).
- `README.md`: framework corrigido de "Next.js 15" para "Next.js 16" (`package.json` já usava `^16.2.7`); estrutura de pastas, seção "CMS Directus" (antes só documentava `products`, agora cobre `categories`/`site_settings`/`faqs`/`privacy_policy`) e passos de setup atualizados para refletir o estado real do projeto (rota `/privacidade`, `scripts/setup-directus-content.mjs`, componentes novos como `Faq`/`SiteSettingsContext`/`PrivacyConsent`).
- `.context/docs/README.md`: "Repository Snapshot" atualizado (removidos `sanity/`/`sanity.config.ts`, inexistentes; adicionados `DESIGN.md`/`PRODUCT.md`).
- Documentação de variáveis de ambiente (`README.md`, `CLAUDE.md`, `GEMINI.md`, `.context/docs/development-workflow.md`, `security.md`, `project-overview.md`) corrigida: a afirmação de que `.env` era "commitado por design" nunca foi verdade neste repo (nunca esteve no git; `.gitignore` sempre bloqueou o nome literal `.env`). Criado `.env.example` (template versionado, sem segredos) como o artefato correto a ser commitado.
- `app/produtos/[slug]/page.tsx` não tinha `export const revalidate` (diferente de `app/page.tsx`, que já usa `revalidate = 3600`) — como página estática gerada via `generateStaticParams`, ficava em cache indefinidamente até o próximo deploy, então editar um produto no Directus nunca chegava a essa página sem redeploy. Também não envolvia a árvore em `SiteSettingsProvider`, então o CTA de WhatsApp nessa rota usava o número/mensagem padrão hardcoded (`SiteSettingsContext.tsx`) em vez dos valores reais cadastrados em `site_settings`.
- Preço e nome de itens já salvos no carrinho (`localStorage`) ficavam congelados no valor do momento em que foram adicionados — uma edição de preço/nome no Directus não chegava a um carrinho já existente nem na mensagem de pedido enviada por WhatsApp. Corrigido pela reconciliação em `lib/use-cart.ts` (ver Adicionado).
- `components/WhatsAppCTA.tsx` usava `bg-green-600` (verde da marca do WhatsApp), inconsistente com o restante do site — padronizado para `bg-primary`, conforme já documentado como drift em `DESIGN.md` ("Don't duplicate the WhatsApp CTA style").

### Adicionado

- Seção "Produtos Relacionados" na página de produto (`components/ProductPageClient.tsx`): abaixo das informações do produto, exibe até 4 outros produtos (priorizando a mesma categoria, com fallback para outras categorias) reutilizando `ProductCard`. A lista é calculada em `app/produtos/[slug]/page.tsx` a partir de `getProducts()`.
- `components/HowItWorks.tsx` redesenhado: o ícone do passo "Finalize pelo WhatsApp" agora é visivelmente maior e preenchido em `bg-primary`, com a linha conectora (mais visível, `bg-primary/25`) centralizada nele — os demais ícones se alinham a essa mesma linha via um slot de tamanho fixo. No mobile, o layout passa de grade para uma lista vertical com ícones à esquerda e título/descrição à direita, ligados por uma linha vertical.
- `.env.example` — template versionado das variáveis de ambiente (`NEXT_PUBLIC_DIRECTUS_URL`, `DIRECTUS_TOKEN`, `SITE_URL`), para substituir a ausência de qualquer baseline commitado.
- Página de produto dedicada em `/produtos/[slug]` (`components/ProductPageClient.tsx`, `components/ProductGallery.tsx`) substitui o pop-up (`ProductDetailModal.tsx`, removido). A rota já existia mas ficava órfã — `ProductCard.tsx` interceptava o clique (`preventDefault`) e abria o modal em vez de navegar. Agora a página tem galeria com miniaturas/swipe, cabeçalho com carrinho real e `CartDrawer` funcionando (antes ausentes nessa rota).
- Selo "Esgotado" com overlay em cinza na imagem e botão "Avise-me" (mensagem de WhatsApp dedicada) quando `in_stock` é `false` no Directus. Produtos sem estoque agora aparecem no catálogo (antes eram ocultados por completo pelo filtro `in_stock: { _eq: true }` em `getProducts()`) — badge "Destaque" e "Esgotado" empilham quando ambos se aplicam.
- Hook compartilhado `lib/use-cart.ts` (estado do carrinho + persistência em `localStorage` + reconciliação): ao carregar, cada item do carrinho é re-sincronizado contra a lista atual de produtos do Directus, por `directusId` (chave estável) com fallback pro slug antigo. Preço e nome desatualizados são corrigidos automaticamente; itens cujo produto foi removido do Directus são marcados `unavailable` e excluídos do total/mensagem, sem serem apagados silenciosamente do carrinho do visitante.
- `lib/whatsapp.ts`: novos builders `buildCartOrderMessage()` (mensagem de pedido do carrinho, antes montada ad-hoc dentro de `CartDrawer.tsx`) e o parâmetro `notifyMe` (mensagem de "avise-me" para produtos esgotados) — centraliza toda a geração de texto do WhatsApp num único lugar.
- `scripts/setup-directus-content.mjs`: nova etapa `configureProductSlugAutomation()` cria (idempotente) um Flow no Directus para gerar o `slug` de `products` automaticamente a partir do `name` a cada criação/edição. **Ainda não está ativo em produção** — criado com `status: "inactive"` porque a mutação do payload pela operação não estava sendo aplicada nos testes manuais, mesmo com a configuração documentada (`trigger: "hook"`, `options.type: "filter"`, `options.return: "$last"`, `accountability: "$full"`); precisa ser depurado no editor visual do Directus (Configurações → Flows) antes de ativar. O campo `slug` permanece editável manualmente até lá. Rótulos em português (`meta.translations`) para os campos de `products` já existiam previamente na instância — nenhuma ação necessária.

### Segurança

- Identificado (não corrigido neste commit) vazamento de um access token do Directus MCP em texto puro no histórico do git, commit `e5aeb54` (`.agents/mcp_config.json`). Decisão: rotacionar o token no painel do Directus, sem reescrever o histórico do git (repo privado). O token vazado também está hoje em `~/.claude.json` (config local do usuário, não versionada) — atualizar lá após a rotação.
- `.gitignore` atualizado para bloquear `.mcp.json` e qualquer `**/mcp_config.json`/`**/mcp-config.json`, evitando repetição do vazamento acima. **Atenção:** `.agents/mcp_config.json` já está rastreado pelo git desde antes dessa regra — o `.gitignore` sozinho não impede que ele continue sendo versionado; para isso é preciso `git rm --cached .agents/mcp_config.json` também.
- `lib/directus.ts`: `staticToken()` agora só é anexado ao cliente Directus quando `DIRECTUS_TOKEN` está definido — antes, o token (inclusive um token admin em ambiente de produção) era sempre enviado, mesmo para as leituras públicas do site, ampliando desnecessariamente o dano de um eventual vazamento. Testado sem token: as 5 collections/singletons (`products`, `categories`, `site_settings`, `faqs`, `privacy_policy`) respondem `200` via a role `Public` do Directus, tanto localmente (`npm run dev`) quanto por `curl` direto na API. Recomendação: **não configurar `DIRECTUS_TOKEN` na Vercel** — deixar as leituras de produção dependerem só da role `Public`; usar um token admin apenas localmente, para rodar `scripts/setup-directus-content.mjs`.
